Lộ trình từ mockup HTML đến chức năng chạy thật trên HRM

Sơ đồ toàn bộ công việc để biến file mockup quan-ly-dinh-bien.html thành phân hệ hoạt động trên web app hiện có (nhà cung cấp giữ source, SQL Server đặt tại máy chủ công ty). Các bước khoanh đỏ là phần công ty tự làm được với IT nội bộ + Claude Code, để cắt khối lượng giao cho đối tác.

Hiện trạng

Mockup đã mô phỏng 6 vai trò (CHT, GDDA, PNS, GDDH, CCM, Admin), luồng duyệt CHT → GDDA → PNS → GDDH, lưu nháp, template dự án, hệ số lương thưởng, theo dõi thực tế/kế hoạch. Dữ liệu đang nằm ở localStorage.

Lợi thế của công ty

Full quyền SQL Server + máy chủ, có IT hạ tầng. Toàn bộ tầng dữ liệu (bảng, view, stored procedure, báo cáo) làm được mà không cần source ứng dụng.

Giới hạn

Không có source ứng dụng → backend (API, kiểm quyền, workflow) và giao diện tích hợp vẫn phải do nhà cung cấp code, build và deploy.

Mục tiêu

Đổi từ "giao mockup" sang "giao gói kỹ thuật": đặc tả + CSDL + SQL logic + API spec + test case → NCC chỉ còn phần nối dây vào app.

Nguyên tắc an toàn khi can thiệp DB

  • Tạo schema riêng (vd dinhbien). Không sửa, không thêm cột vào bảng của NCC; chỉ tham chiếu khóa ngoại hoặc đọc qua view.
  • Mọi script SQL nằm trong Git, đánh số chạy tuần tự, có script rollback tương ứng.
  • Chỉ chạy trên database bản sao (restore từ backup) cho tới khi NCC duyệt. Production chỉ chạy sau khi backup full.
  • Đặt quy ước tên, kiểu dữ liệu, collation theo đúng chuẩn DB hiện có (Claude Code đọc schema rồi bắt chước).
  • Logic duyệt và kiểm quyền vẫn phải nằm ở backend của NCC; SQL của bạn không thay được kiểm quyền phía server.
  • Ghi rõ trong biên bản: phần nào bạn viết, phần nào NCC bảo hành, để lỗi phát sinh không thành tranh chấp.

Điểm đàm phán với nhà cung cấp

  • Yêu cầu NCC báo giá theo WBS (từng hạng mục như bảng chi tiết) trước, sau đó trừ hạng mục công ty nhận.
  • Đề xuất NCC chỉ báo giá: tích hợp kiến trúc, backend/API, frontend, unit test, deploy, bảo hành. Phần đặc tả, CSDL, SQL, test UAT, đào tạo công ty tự làm.
  • Rút deadline: NCC không cần giai đoạn BA và thiết kế CSDL, có thể bắt đầu code ngay khi nhận gói bàn giao.
  • Ghi điều khoản: công ty sở hữu phần SQL tự viết; NCC review trong X ngày; lỗi do script công ty thì công ty sửa.
  • Xin NCC cấp môi trường test (bản sao app trỏ vào DB test) để UAT không đụng production.

Câu hỏi cần hỏi NCC trước khi bắt đầu

  1. App viết bằng gì (ASP.NET / .NET Core / Java / PHP…), frontend framework nào?
  2. Truy cập DB qua ORM (Entity Framework, Dapper…) hay stored procedure? Có chấp nhận gọi SP do công ty viết không?
  3. Cơ chế user, vai trò, phân quyền menu đang lưu ở bảng nào? Thêm vai trò CHT/GDDA/GDDH/CCM theo dự án bằng cách nào?
  4. Có module workflow duyệt và gửi mail dùng chung không, hay viết riêng cho phân hệ này?
  5. Có môi trường test/staging riêng không? Quy trình deploy và ai giữ quyền deploy?
  6. App có API công khai hoặc SSO để sau này công ty gắn công cụ riêng vào không?
  7. Quy ước đặt tên bảng/cột, kiểu khóa chính (int identity hay GUID), có dùng soft-delete, audit log không?

Phương án B: module vệ tinh (mức tự chủ cao hơn)

Công ty tự xây một web app riêng cho định biên trên máy chủ của mình, đọc/ghi cùng SQL Server, NCC chỉ thêm một menu dẫn link và cấp SSO.

  • Được: tự chủ gần như hoàn toàn, sửa đổi không phụ thuộc NCC.
  • Mất: phải tự lo bảo mật, đăng nhập, sao lưu, vận hành lâu dài; IT hạ tầng chưa có dev thì rủi ro cao.
  • Khi nào nên: sau khi làm xong phương án A, đội đã quen làm SQL và có thêm ít nhất 1 dev nội bộ.

Sơ đồ phía trên là phương án A (tích hợp vào app của NCC), phù hợp nguồn lực hiện tại.

Thứ tự nên làm ngay: B0.1 khảo sát schema → B0.3 chốt mô hình hợp tác + xin báo giá WBS → B1.2–B1.4 đặc tả và test case từ mockup → B2.1 thiết kế CSDL gửi NCC review. Bốn việc này không cần source, làm song song với lúc NCC đọc mockup.
